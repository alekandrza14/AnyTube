# AnyTube

Видеохостинг, который берёт видео из публичных GitHub-репозиториев с именем `anytubevideo_*` (или с topic `anytubevideo`).
Пример: `autor/anytubevideo_myvideo` с файлом `myvideo.mp4`.

Возможности: лента, поиск, каналы авторов, плеер с перемоткой, скачивание, поддержка Git LFS, страница-инструкция `/upload`.

## Запуск локально
```
npm install
set GITHUB_TOKEN=ghp_xxx      # Linux/macOS: export GITHUB_TOKEN=ghp_xxx
npm start
```
Открыть http://localhost:3000

## Деплой на Render
1. Залейте эту папку в свой репозиторий GitHub (например `anytube`).
2. На https://dashboard.render.com → **New → Blueprint** → выберите репозиторий (Render прочитает `render.yaml`).
   Или **New → Web Service**: Build `npm install`, Start `npm start`.
3. Создайте токен: GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained**, доступ только к публичным репозиториям, без прав. Вставьте его в переменную `GITHUB_TOKEN` на Render.
   Без токена GitHub даёт всего 60 запросов в час — сайт быстро упрётся в лимит.

## Переменные
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `GITHUB_TOKEN` | — | токен GitHub (очень желателен) |
| `CACHE_MINUTES` | 10 | как часто обновлять список видео |
| `MAX_SEARCH_PAGES` | 10 | страниц поиска по 100 репо |
| `SITE_URL` | — | адрес сайта, например https://anytube.onrender.com |
| `VIDEO_DIRECT` | on | бесплатные видео браузер грузит **прямо с GitHub** (raw / LFS) — трафик Render не тратится; если прямая ссылка не сыграла, страница сама переключается на `/video/…` через сервер. `off` — всё через сервер |

## 💰 Букс: настройка
Букс — реклама видео за деньги и заработок на просмотрах (как aviso.bz): `/bux`, админка `/bux-admin`.

1. **База (обязательно!)** Создайте **приватный** репозиторий, например `anytube-db` (пустой).
   Токен: GitHub → Settings → Developer settings → Fine-grained tokens → доступ **только к anytube-db**, Permissions → Contents: **Read and write**.
   На Render: `DB_REPO=alekandrza14/anytube-db`, `DB_TOKEN=github_pat_…`.
   Без этого балансы хранятся в файле, который бесплатный Render стирает при каждом перезапуске.
2. **Вход через GitHub.** GitHub → Settings → Developer settings → **OAuth Apps → New OAuth App**:
   Homepage URL `https://anytube.onrender.com`, Authorization callback URL `https://anytube.onrender.com/auth/callback`.
   Client ID → `GITHUB_CLIENT_ID`, Generate a new client secret → `GITHUB_CLIENT_SECRET`.
3. **Пополнение через ЮMoney.** Номер кошелька → `YOOMONEY_WALLET`.
   В ЮMoney откройте настройки HTTP-уведомлений: адрес `https://anytube.onrender.com/api/yoomoney/notify`, секрет → `YOOMONEY_SECRET`.
   Нажмите «Протестировать»: в логах Render должно появиться `тестовое уведомление ЮMoney получено, подпись верна`.
4. `SESSION_SECRET` Render создаст сам (если не через Blueprint — впишите любую длинную случайную строку).

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `ADMIN_LOGIN` | alekandrza14 | GitHub-логин администратора |
| `PAYOUT_EMAIL` | alekandrza14@gmail.com | куда приходят заявки на вывод |
| `BUX_COMMISSION` | 0.25 | доля AnyTube с просмотра (зритель получает 75%) |
| `BUX_MIN_WITHDRAW` | 10 | минимум для вывода, ₽ |
| `BUX_MIN_TOPUP` | 10 | минимум пополнения, ₽ |
| `BUX_LIKE_PRICE` | 2 | цена одного плюсика для заказчика, ₽ |
| `BUX_DISLIKE_PRICE` | 5 | цена одного дизлайка для заказчика, ₽ |
| `BUX_MIN_ACCOUNT_DAYS` | 7 | минимальный возраст GitHub-аккаунта, чтобы зарабатывать |

**Тарифы** (цена просмотра для рекламодателя, зритель получает 75%): 15 с — 0,10 ₽; 30 с — 0,18 ₽; 45 с — 0,25 ₽; 60 с — 0,30 ₽; 90 с — 0,40 ₽; 120 с — 0,50 ₽. Меняются в `bux.js` (`TARIFFS`).

**Защита от накрутки:** вход только через GitHub, аккаунт старше 7 дней; одно видео — раз в 24 часа на человека и на IP; таймер считает время, только пока видео играет во вкладке, сервер сверяет реальное время; в конце нужно нажать показанную цифру; один просмотр одновременно; блокировка пользователей в админке.

**Вывод:** зритель заполняет заявку с обоснованием, сумма замораживается, открывается письмо на `PAYOUT_EMAIL`. Администратор переводит деньги в приложении ЮMoney и нажимает «Выплачено» в `/bux-admin` (или «Отклонить» — деньги вернутся пользователю).

## ➕ Плюсики (вместо звёзд GitHub)
Под каждым видео кнопка «+» — ставится **без входа через GitHub** (сайт запоминает браузер cookie-файлом, с одного IP — один лайк на видео, повторное нажатие убирает лайк).
«Топ» сортируется по плюсикам AnyTube; звёзды GitHub больше не учитываются и не показываются — накручивать их опасно для аккаунтов.
В буксе можно заказать плюсики любому видео: `BUX_LIKE_PRICE` (по умолчанию 2 ₽), исполнитель смотрит 15 с и плюсик ставится автоматически.

## 👎 Букс: дизлайки за деньги
Заказчик (вкладка «Заказать») выбирает **любое** видео AnyTube (своё или чужое), **уровень 1–5** и количество. Цена — `BUX_DISLIKE_PRICE` (по умолчанию 5 ₽), исполнитель получает 75%.
Исполнитель ставит дизлайк через AnyTube Uploader (вкладка «Дизлайк») и нажимает «Проверить»: сайт по API GitHub ищет у него репозиторий
`anytubecomment_<автор>_<файл>_Commet.<уровень>.diske`. Перепутан уровень — сайт подскажет, какой стоит и какой нужен, и не заплатит.
Один человек — один оплаченный дизлайк на видео; себе и автору видео задания не показываются.

## 🛒 Магазин: платные видео, приложения, обои
Загрузчик (AnyTube Uploader) умеет выкладывать:
- **видео** — бесплатно, **почасово** (например 6 ₽/час, списывается поминутно, только пока видео играет) и/или **покупкой навсегда**; без оплаты виден бесплатный трейлер;
- **рекламу приложения** — ролик бесплатный, само приложение: бесплатно, **покупка** или **подписка** на час / день / месяц / год (продление складывается);
- **анимированные обои** — бесплатно (скачивается оригинал, в т.ч. GIF) или платно (на сайте лёгкое превью).

Платные файлы лежат в **приватных** репозиториях автора `anytubepaid_*`, загрузчик приглашает туда аккаунт сайта (alekandrza14), сайт **сам принимает приглашения** и отдаёт файлы только тем, кто заплатил.
Оплата — с баланса букса (сначала пополненный, потом заработанный). Автор получает `1 − SALE_COMMISSION` (при `SALE_COMMISSION=0.37` — 63%). Проверенные авторы и модераторы получают 90%, особые ставки (до 90% — модераторы с правом «доли», до 150% — администратор) назначаются на `/moderation` → «Доли авторов» с обязательным обоснованием; процент виден рядом с аватаркой автора на заработанный баланс и выводит как обычно.

**Настройка:** `PAID_TOKEN` — classic-токен аккаунта **alekandrza14**: github.com/settings/tokens/new → Tokens (classic) → галочка **repo** → Generate.

## 🎮 WebGL-игры и 🧊 3D-модели
- **Игра** — папка WebGL-сборки (Unity, Godot, Construct, Phaser, любая HTML5) в отдельном репозитории: бесплатная — публичный `anytubevideo_<имя>_game`, платная — приватный `anytubepaid_<имя>`. В `anytube.json`: `"kind": "game"`, `"game"` (или `"paid": {"game"}`) = `{repo, dir, entry}`.
  Цены: `per_hour` (например 100 коп. = 1 ₽/час, списывается поминутно и **точно**: копейки за минуту копятся дробно) и/или `buy`.
- Игра открывается по адресу `/play/<подписанный ключ>/…` в `<iframe sandbox>` без `allow-same-origin` + заголовок `Content-Security-Policy: sandbox`: у кода игры «пустой» источник, он не видит куки и не может вызывать API сайта от имени игрока. Все POST-запросы с чужим `Origin` (в том числе `null` из игры) сайт отклоняет.
- Файлы Git LFS (больше 95 МБ) сайт распознаёт и берёт из LFS сам; `.br`/`.gz` отдаются с `Content-Encoding`, `.wasm` — как `application/wasm`.
- Сохранения HTML5-игр (localStorage) пересылаются странице и хранятся в браузере игрока. Сохранения Unity через IndexedDB в песочнице не работают.
- **3D-модель** — `"kind": "model"`, файлы как у приложения (бесплатно или `buy`). `.glb` показывается в 3D прямо на странице (`<model-viewer>`).

## 🖼 Живые обои с установщиком
Кнопка «Скачать обои с установщиком» отдаёт zip, собранный на лету: `wallpaper.<ext>` (оригинал обоев) + проигрыватель из папки `wallpaper-kit/`
(`live_wallpaper.py`, `install.cmd`, `start.cmd`, `stop.cmd`, `autostart.cmd`, `README.txt`). Платные обои — только после покупки.
Пользователь распаковывает архив и запускает `install.cmd`: он ставит Python и библиотеки при необходимости, копирует обои в
`%LOCALAPPDATA%\AnyTube\LiveWallpaper`, запускает их под иконками рабочего стола и спрашивает про автозапуск.
Чтобы обновить проигрыватель у всех — просто замените файлы в `wallpaper-kit/`.

## 📱 Пополнение по СБП
`SBP_PHONE`, `SBP_BANK`, `SBP_NAME` — реквизиты видны только вошедшим пользователям. Пользователь получает код (`AT123456`), переводит по СБП с кодом в комментарии и жмёт «Я перевёл». Администратор находит перевод в приложении банка и нажимает «Зачислить» в `/bux-admin` (можно вписать фактически пришедшую сумму).

## 🛡 Модерация
- У каждого видео и комментария есть «⚠ Пожаловаться» → страница `/report` (правила, контакты, форма жалобы). Жаловаться можно без входа, не больше 10 жалоб в час с одного интернета.
- В подвале всех страниц — «Сообщить о нарушении» и контакты: `CONTACT_EMAIL` (по умолчанию `PAYOUT_EMAIL`) и `CONTACT_PHONE` (по умолчанию `SBP_PHONE`).
- `/moderation` (только `ADMIN_LOGIN`): очередь жалоб, скрыть видео / комментарий, заблокировать автора (скрываются все его видео, комментарии и дизлайки, закрывается букс), разблокировать, список всех комментариев.
- Скрытие не удаляет файлы на GitHub — только убирает с AnyTube. Дубли и скрытые видео — также в `/bux-admin`.
- **Премодерация** (`PREMODERATION`, по умолчанию `on`): новое видео не видно в ленте, поиске, обоях и буксе, пока администратор не нажмёт «✅ Одобрить» во вкладке «⏳ На проверке». Автор видит своё видео по ссылке с пометкой «на проверке», при отклонении — причину. Видео администратора и «⭐ доверенных авторов» публикуются сразу. При первом включении всё уже опубликованное одобряется автоматически. `PREMODERATION=off` — публиковать без проверки.

## Ограничения
- Бесплатный Render засыпает после 15 минут без запросов; первый заход после сна — ~30–60 с.
- Бесплатные видео идут прямо с GitHub и трафик Render не тратят. Через сервер идут только платные видео и файлы (приватные репозитории), игры и архивы обоев — бесплатный план Render включает 5 ГБ исходящего трафика в месяц.
- Видео в Git LFS тратят LFS-трафик владельца репозитория на GitHub (у бесплатного аккаунта он ограничен). Режим «части по 95 МБ» в Uploader LFS не использует.
- Обычные файлы в GitHub — до 100 МБ; больше — только через Git LFS (у которого своя квота).
